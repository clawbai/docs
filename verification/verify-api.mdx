---
title: Verification API (v1)
---

This page describes the provider-facing Verification API.

Goal: help API providers answer “should I trust this agent request?”

---

## Auth
Providers use a **provider API key**.

Accepted headers:

```http
X-Clawb-Api-Key: ck_live_...
```

or:

```http
Authorization: Bearer ck_live_...
```

---

## Verify an agent request (online)

Clawb verifies the agent’s Ed25519 signature over the canonical string:

```
METHOD\nPATH\nTIMESTAMP_MS\nNONCE\nBODY_SHA256
```

Request:

```http
POST /v1/verify
Content-Type: application/json
X-Clawb-Api-Key: ck_live_...

{
  "agent_id": "agt_...",
  "method": "POST",
  "path": "/v1/refunds",
  "timestamp_ms": 1700000000000,
  "nonce": "n_123",
  "body_sha256": "<lowercase-hex>",
  "signature_b64": "<base64>"
}
```

Timestamp must be `milliseconds`; using `seconds` causes signature validation failure.

Request field notes:
- `method`: use uppercase HTTP method (`GET`, `POST`, and so on)
- `path`: include only the path (`/v1/refunds`), not scheme, host, or query string
- `timestamp_ms`: unix epoch milliseconds from `X-Clawb-Timestamp`
- `nonce`: pass through the exact `X-Clawb-Nonce` value
- `body_sha256`: lowercase hex SHA-256 of the exact raw request body bytes
- `signature_b64`: pass through the exact `X-Clawb-Signature` value

### Response

```json
{
  "valid": true,
  "agent_id": "agt_...",
  "verification_tier": "attested",
  "risk_tier": "low",
  "revoked": false,
  "disclosure": {
    "disclosed": {
      "...": "..."
    }
  }
}
```

Notes:
- `owner` fields may be omitted when disclosure is disabled.
- Providers should not treat omitted identity as a failure.
- `response_signature` lets you verify the response is authentic.

## Offline verification (optional)
For low-latency or high-volume integrations, agents can include an **assertion token** (JWT-like) that providers can validate locally.

Recommended approach:
- validate the token signature using Clawb’s public keys
- enforce short expirations
- optionally call `/v1/verify` for revocation checks or higher-risk operations

---

## Error modes
Expected errors:
- `401` missing or invalid provider API key
- `429` rate limited / quota exceeded
- `400` malformed request
- `200` with `valid=false` for signature failures (enumeration-safe)

---

## Provider feedback (reputation signals)
Providers can submit feedback to improve ecosystem safety.

```http
POST /v1/reputation/feedback
Authorization: Bearer prv_...
Content-Type: application/json

{
  "agent_id": "agt_...",
  "signal": "abuse_suspected",
  "severity": "high",
  "evidence": {
    "request_ids": ["..."],
    "notes": "credential stuffing pattern"
  },
  "timestamp": "2026-02-11T20:11:12Z",
  "signature": "base64:..."
}
```

Clawb rate-limits and attributes feedback, and uses it as an input signal for reputation.
