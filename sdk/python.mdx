This page is a **step-by-step** guide to using the Clawb Python SDK.

It covers both perspectives:

- **Agent owners** (your agent runtime): register → attest → claim, then make **signed** calls.
- **API providers / relying services** (your backend API): verify + check using a **provider API key**.

> Base URL
>
> Most examples use:
> 
> - `https://api.clawb.ai/api`
>
> The `/api` prefix is part of the base URL.

---

## Install

```bash
pip install clawb-agent-sdk
```

Python requirement: **3.9+**.

---

## Mental model (read this first)

### Identities

- **`agent_id`**: the agent’s stable identifier in Clawb (example: `agt_...`).
- **Ed25519 keypair**: used to sign requests.
  - **public key** can be shared
  - **private key** must be kept secret by the agent runtime

### Two phases

1) **Onboarding (one-time per agent identity)**
   - Create keys
   - Register
   - Attest
   - (Optional) Claim for dashboard ownership

2) **Request-time (every request)**
   - Agents send **signed** requests to Clawb (telemetry, vault, etc.)
   - API providers call Clawb **server-to-server** to **Verify** and/or **Check**

---

## Part A — Agent onboarding (Register → Attest → Claim)

### Step 1 — Generate keys (Ed25519)

```python
from clawb_agent_sdk import ClawbClient

# Generate an Ed25519 keypair locally.
# - priv_b64: base64 PKCS8 private key (KEEP SECRET)
# - pub_b64: base64 public key (safe to share)
priv_b64, pub_b64 = ClawbClient.generate_ed25519_keypair_b64()

print("public_key_b64:", pub_b64)
```

**Why this matters:** Clawb never needs your private key. Your agent signs with it.

---

### Step 2 — Register (unsigned)

Register creates an `agent_id` and returns a challenge.

SDK call:

```python
base_url = "https://api.clawb.ai/api"

client = ClawbClient(base_url=base_url)
reg = client.register(
    name="my-agent",
    public_key_b64=pub_b64,
    # key_type defaults to "ed25519"
    metadata={"source": "python-sdk"},
)

print(reg)
```

#### Register payload (what is sent)

The SDK sends:

```json
{
  "name": "my-agent",
  "public_key": "<public_key_b64>",
  "key_type": "ed25519",
  "metadata": {"source": "python-sdk"}
}
```

#### Register response (what you get back)

You’ll receive JSON that includes (at minimum):
- `agent_id`: your new agent identifier
- `challenge_id`: id for the attestation challenge
- `challenge`: base64 challenge bytes

---

### Step 3 — Attest (unsigned)

Attestation proves you own the private key corresponding to the public key you registered.

SDK call:

```python
agent_id = reg["agent_id"]

# Create a client that can sign (agent-owned)
agent_client = ClawbClient(
    base_url=base_url,
    agent_id=agent_id,
    private_key_b64=priv_b64,
)

att = agent_client.attest(
    challenge_id=reg["challenge_id"],
    challenge_b64=reg["challenge"],
)

print(att)
```

#### What’s happening here

- Clawb gave you a challenge (random bytes, base64).
- The SDK signs those bytes with your private key.
- Clawb verifies the signature and marks the agent as “attested” (or keeps it pending based on your workflow).

---

### Step 4 — Claim code (signed)

Claiming is a **dashboard ownership** step.

- Useful when a human wants to manage the agent in the dashboard.
- Not strictly required for all provider-only use-cases.

SDK call:

```python
claim = agent_client.request_claim_code()
print(claim)

# The response typically includes:
# - claim_code
# - claim_url (open in browser)
# - expires_at
```

## Part B — Telemetry (signed)

Telemetry is how your agent reports health + outcomes to Clawb.

### What endpoint to call

- **Endpoint:** `POST /v1/telemetry/heartbeat`
- **Auth:** agent-signed (the SDK adds signing headers automatically when you use `ClawbClient(..., agent_id, private_key_b64)`)

### Recommended cadence

- Send a heartbeat periodically (for example every **30–60 seconds**).
- For bursty agents, you can send heartbeats only when work happens.

### Heartbeat fields (payload)

```json
{
  "agent_id": "agt_...",
  "status": "ok",
  "latency_ms": 123
}
```

Field meaning:
- `agent_id` (string, required): the agent identity.
- `status` (string, optional): usually `ok` or `error`.
- `latency_ms` (number, optional): how long the last operation took.

### Example: send a heartbeat (SDK)

```python
# A client that can sign agent-owned requests
agent_client = ClawbClient(
    base_url=base_url,
    agent_id=agent_id,
    private_key_b64=priv_b64,
)

resp = agent_client.post(
    "/v1/telemetry/heartbeat",
    json={
        "agent_id": agent_id,
        "status": "ok",
        "latency_ms": 123,
    },
)

print("http_status:", resp["status"])
print("json:", resp["json"])
```

### Example: heartbeat loop (safe + simple)

```python
import time

while True:
    t0 = time.time()

    # ... do work here ...

    latency_ms = int((time.time() - t0) * 1000)

    agent_client.post(
        "/v1/telemetry/heartbeat",
        json={"agent_id": agent_id, "status": "ok", "latency_ms": latency_ms},
    )

    time.sleep(60)
```

### Common mistakes

- **Signing not configured:** if you create `ClawbClient(base_url=...)` without `agent_id` and `private_key_b64`, signed calls will fail.
- **Hash mismatch (if you implement signing yourself):** the signature uses `SHA256(body)` of the raw bytes.

## Part C — API providers (Verify + Check) using ApiProvider helpers

API providers are server-side backends that receive requests from agents.

They typically:

1) **Verify** the agent signature (locally or via `/v1/verify`)
2) **Check** authorization via `/v1/check`

Both endpoints are designed for **server-to-server** usage and require a **provider API key**.

<Info>
  **Auth quick reference**

  ```http
  # Preferred
  X-Clawb-Api-Key: ck_live_9f2b3c4d5e6f7a8b

  # Alternative
  Authorization: Bearer ck_live_9f2b3c4d5e6f7a8b
  ```

  Use provider keys with the `ck_live_` or `ck_test_` prefix.
</Info>

### Setup

```python
from clawb_agent_sdk import ClawbClient, ApiProvider

base_url = "https://api.clawb.ai/api"
provider_api_key = "ck_live_9f2b3c4d5e6f7a8b"  # provider key issued in the dashboard

provider_client = ClawbClient(base_url=base_url)
api = ApiProvider(client=provider_client, api_key=provider_api_key)
```

---

### Step 1 — Online verify (optional)

Use this if you want Clawb to validate the agent signature for you.

You must build the payload from the **original inbound request** that your API received.

Required fields:
- `agent_id`: from `X-Clawb-Agent-Id`
- `method`: uppercase HTTP method (e.g. `POST`)
- `path`: URL path only (e.g. `/v1/refunds`)
- `timestamp_ms`: unix epoch milliseconds from `X-Clawb-Timestamp`
- `nonce`: from `X-Clawb-Nonce`
- `body_sha256`: lowercase hex SHA-256 of the raw request body bytes
- `signature_b64`: from `X-Clawb-Signature`

Timestamp must be `milliseconds`; using `seconds` causes signature validation failure.

Example:

```python
# Example inbound request values (you would read these from your framework)
agent_id = "agt_..."
method = "POST"
path = "/v1/refunds"
timestamp_ms = 1700000000000
nonce = "n_123"
raw_body = b'{"amount":49.00}'

body_sha256 = api.sha256_hex(raw_body)
signature_b64 = "..."  # from X-Clawb-Signature

verify_out = api.verify(
    agent_id=agent_id,
    method=method,
    path=path,
    timestamp_ms=timestamp_ms,
    nonce=nonce,
    body_sha256=body_sha256,
    signature_b64=signature_b64,
)

print(verify_out)
# verify_out["valid"] is True/False
```

---

### Step 2 — Check authorization (required)

Once you’re satisfied the agent is who it says it is, ask Clawb for a policy decision.

```python
decision = api.check(
    agent_id=agent_id,
    policy_id="pol_default",
    action="refund",
    context={"amount": 49.00, "currency": "USD"},
)

print(decision)
# decision["decision"] is "allow" | "challenge" | "deny"
```

## Part D — Vault helpers (agent-signed)

If your agent uses Vault:

```python
from clawb_agent_sdk import VaultProvider

vault = VaultProvider(client=agent_client)

# Example: evaluate access
out = vault.policy_eval(secret_set_id=123, action="export", keys=["OPENAI_API_KEY"], environment="prod")
print(out)
```

clawb-agent bootstrap --base-url https://api.clawb.ai/api --name "my-agent"
