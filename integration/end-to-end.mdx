This scenario shows a complete refund flow.

## 1) Receive inbound signed request

Extract:

- `X-Clawb-Agent-Id`
- `X-Clawb-Timestamp` (milliseconds)
- `X-Clawb-Nonce`
- `X-Clawb-Signature`

## 2) Verify identity

Use local verification or online `/v1/verify`.

```python
verify_result = provider.verify(
    agent_id=agent_id,
    method="POST",
    path="/v1/refunds",
    timestamp_ms=timestamp_ms,
    nonce=nonce,
    body_sha256=provider.sha256_hex(raw_body),
    signature_b64=signature_b64,
)
if not verify_result.get("valid"):
    raise ValueError("invalid signature")
```

## 3) Request policy decision

```python
decision = provider.check(
    agent_id=agent_id,
    policy_id="pol_refunds_v2",
    action="refund",
    context={"amount": 249.00, "currency": "USD", "reason": "duplicate_charge"},
)
```

Branch on decision:

- `allow`: continue
- `challenge`: pause and route to approval
- `deny`: block

## 4) Optional: mint short-lived credential for follow-on API call

```python
mint = provider.identity_credentials_mint(
    agent_id=agent_id,
    provider="payments",
    audience="clawb.provider",
    ttl_seconds=120,
    one_time=True,
    scopes=["refund:execute"],
)
```

Use the returned token only for the bounded operation.

## 5) Record and query audit

```python
# Later, operations can query recent denies/challenges.
audit = provider.provider_audit_events(agent_id=agent_id, limit=20)
```

## 6) Emergency branch

If compromise is suspected:

```python
provider.identity_kill_switch_minting(paused=True, reason="incident INC-404")
provider.identity_kill_switch_revoke_all(reason="incident INC-404")
```

## Troubleshooting quick checks

1. Timestamp must be milliseconds.
2. `path` must match exactly.
3. Request body hash must use exact raw bytes.
4. Provider key must match workspace where `agent_id` lives.
5. Handle `403` policy errors separately from network failures.
